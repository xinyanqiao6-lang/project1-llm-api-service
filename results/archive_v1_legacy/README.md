# v1 旧口径压测结果（大部分已作废，仅作留档）

这些是 2026-08-27 ~ 08-29 生成的压测结果。**默认全部不可写进简历、不可用于面试引用。**
归档在这里是为了留证据：它们是三个数字硬伤的原始现场。

> ⚠️ **例外**：下面「例外轮次」一节列出的 3 个文件，经逐字段核验**未被那三个硬伤污染**，
> 目前仍被简历引用。若你要引用任何数字，请先看该节，不要照搬本目录的默认结论。

## 为什么作废

| 硬伤 | 表现 | 证据 |
|---|---|---|
| QPS 把被拒请求算进分子 | `loadtest_20260827_164822.json`：报 1010.8 QPS，实际成功 8 个 / 被拒 30316 个，真实成功吞吐 0.3 QPS | 虚高约 3000 倍 |
| 延迟分位数混入 429 | `loadtest_20260827_164115.json`：P50 = 3.2ms —— 那是 429 拒绝响应的耗时，不是推理耗时 | 真实 P50 量级为数百 ms |
| 命中率用进程累计值 | 多轮 `hit_rate` 高达 0.99+ | `/stats` 是进程累计值，多轮互相污染 |

另外还有两个更隐蔽的问题，同样让这些数字不可信：

4. **压测器反馈崩塌**：闭环不限速发包，上游一报错就打出 1400 req/s，把上游压垮。
5. **系统代理劫持**：本机 `HTTP_PROXY` 已设置但 `NO_PROXY` 不含 `127.0.0.1`，
   httpx 默认 `trust_env=True`，打向本地网关的请求被代理劫持并一律返回 404。
   （注意：本目录里的文件是在此问题被发现之前跑的，部分数字可能已被代理污染。）

## 例外轮次（2026-10-08 逐字段核验，仍可引用）

上面三个硬伤**不是每一轮都命中**。以下 3 个文件经解析原始 JSON 确认不受影响：

| 文件 | 用途 | 关键证据 |
|---|---|---|
| `loadtest_20260828_103953.json` | 热路径（缓存命中） | `limit=100000` / `rejected_total=0` → 无 429 混入；`hits 5030 / misses 1` → 命中率可自洽校验；`backend=redis` |
| `loadtest_20260829_095823.json` | 冷路径（韧性优化后） | 同上无 429 混入；`hits 0 / misses 109` 干净；`circuit_breaker.state=closed` 且 `consecutive_failures=0`（证明跑在熔断防线之后） |
| `loadtest_20260828_103903.json` | 冷路径（**优化前**，用于对比） | `P99=60004.0` 正是上游 60s 挂起现场，与优化后的 3760.1ms 构成闭环 |

**为什么这三轮例外**：判定作废的三条硬伤都要求「有 429 混入」或「命中率取累计值」，
而这三轮 `rate_limit.limit = 100000`（阈值调到 10 万）、`rejected_total = 0`，
不存在被拒请求污染；命中率是本轮 `hits/misses` 而非跨轮累计。

**残留风险（如实告知）**：本目录 README 开头提到"部分数字可能已被系统代理污染"，
这一条无法从数据本身排除；另外热路径 335 QPS 是开环压出去的，不受闭环反馈控制。
**若要彻底消除顾虑，用下方命令重跑一轮，新数据带 `_resume` 后缀即可直接引用。**

引用这三轮数据时的口径要求：
- 热路径命中率 **99.98%** 必须说明用的是 `repeat=1.0`（重复同一问题、预热后全命中），代表**缓存命中路径的性能上限**，非真实流量命中率。
- 限流「6,354 全部 429」出自 `loadtest_20260827_164115.json`，该轮 `backend=in-memory(fallback)` 是**内存后端**，别说成"Redis 下测出"。
